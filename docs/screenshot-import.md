# Screenshot Uma import

The Umas page accepts pasted, dropped or selected PNG/JPEG/WebP images in one batch. Screenshots stay in the browser; no screenshot is sent to a service or external model. The app bundles Tesseract.js 7, the English `best_int` language model and its local WebAssembly worker from pinned npm dependencies. Vite emits those assets for both development and packaged desktop builds.

The detector finds colored skill icons beside lavender, gold or rainbow card backgrounds. The five-column stats row is detected independently of the title, including title-free crops, and excludes portrait/rating decorations. Separate identity and aptitude masks suppress other screen regions; the five stat cells and skill cards have their own OCR passes. It crops away the icons and isolates brown text, then reads a contact sheet with fixed row boundaries. Only those card readings may create skills; only the identity/aptitude masks supply outfit/character landmarks. A dedicated digit-only pass reads the five stat cells. Captured aptitudes populate the build's ten saved grades; missing grades use that outfit's catalog defaults.

Closing the screenshot dialog preserves images, corrections, selections and ongoing OCR for the current app session. Clear stops OCR and resets that draft. Successfully saving an imported Uma clears its screenshot draft; cancelling the editor or a failed save retains it. A run cleared during processing cannot repopulate the result afterward.

Saved builds retain all ten aptitudes. The daily GameTora catalog supplies outfit defaults, with bundled defaults available offline. Participant surface/distance/style choices are separate race overrides; changing the course or strategy resolves the corresponding saved grade. A `!` marker identifies a changed active grade and resets it when clicked. Old setups retain their explicit grades as overrides. Editing a build updates changed aptitude baselines while retaining unrelated overrides. Overrides are never written back to the Uma library.

Recognition matches the current reference catalog, compares skill icons with bundled game-icon templates, distinguishes explicit ○/◎ marks, resolves the owner's native unique, preserves its level and merges repeated IDs. A rainbow background plus a visible unique level allows a strong native-skill match to recover the owning outfit when identity text is missing. Conflicting header/unique identities require review; inherited names alone never establish ownership. Manual native-unique correction can also establish its owner. Icon evidence distinguishes similar Global/JP names without guessing a region from the name alone. Missing marks, weak matches and unreadable partial cards require a choice or dismissal. Each uncertain skill has an editable fuzzy search across eligible catalog skills, including partial names and OCR spelling errors. “Skip this text” dismisses only that label and keeps the screenshot. A partial label already covered by a fully read skill is ignored. Conflicting stats remain blank. The result opens in the existing Uma editor and is saved only through its normal save flow.

Limits: 24 screenshots per Uma, 12 MiB per file, 24 megapixels per source image. The first implementation reads English game screenshots; JP text requires another language model. Unknown layouts and low-quality crops remain reviewable rather than silently supplying default stats. Cancellation terminates the OCR worker.

Runtime and core: Apache-2.0, https://github.com/naptha/tesseract.js and https://github.com/naptha/tesseract.js-core. Complete runtime/core licenses ship in `ocr/`. English trained data: https://github.com/naptha/tessdata; its npm wrapper is `@tesseract.js-data/eng` (MIT).

`tests/ocr-workflow.ts` checks public synthetic landmarks and catalog matching. Private screenshots are validated locally and are not committed as fixtures.
